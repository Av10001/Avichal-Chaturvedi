PROJECT // 01 · BOARD + FIRMWARE 2026 · ENERGY SECTOR

Direct-Air-Capture Test Instrument

One networked board for a laboratory reactor: temperature sensing, heater control and valve sequencing. Built for a global energy company, it replaced a bulky and costly imported instrument.

2-Layers 200 × 250 mm 224 Parts Two MCUs, Safe State
Role Sole Board Designer, Co-author of Firmware
Specification 5 thermocouple inputs, 2 PID heater loops, valve drivers, load-current monitoring, wired Ethernet, onboard mains supply.

Hardware Engineering

  • Noisy and quiet halves: Mains and the heater relays sit on one side of the board and the thermocouple inputs on the other, with the supplies between them, so switching noise stays out of microvolt readings.
  • Companion MCU for valves: A second, simpler microcontroller drives the solenoid valves and has a dedicated safe-state command. The main controller polls it every two seconds.
  • Load-current monitoring: Current monitors on each heater and on the system rail let firmware tell a failed load from a healthy one.

Firmware Architecture

Task Period Operation
sensor500 msThermocouples, currents, heater feedback
pid100 msBoth heater PID loops
link_poll2000 msValve status from companion MCU
[ STX | CMD | DATA | SEQ | CRC | ETX ] → GET_STATUS, SET_SOLENOIDS, SAFE_STATE

Protocols & Test

  • PC link: JSON over UDP with command IDs, sequence numbers, a CRC and a session handshake.
  • Graded faults: An open thermocouple invalidates that channel. A temperature alarm is only logged.
  • PID auto-tune: Relay-oscillation test on the real heater, with three tuning choices.
  • Automated test: A Python script checks every sensor, valve and heater step over the network and writes a dated PDF report.
  • Result: Three years of operation with one unit ordered each year, all still working. The fourth order is in progress and completes in December. The first unit ran about 2 years before its first maintenance and upgrade. Accuracy is ±1%. The latest order upgrades the earlier units from USB to this LAN version.
  • Noise fix: Readings fluctuated at random. Changing one variable at a time showed about 10 mV of noise coupling from the vessel body into the thermocouple. Proper body earthing plus a 10 µF capacitor on the sensor module made it stable.
Codebase: 3,768 lines C · 708 lines C++ (Companion) · 1,980 lines Python test and tuning tools

PROJECT // 02 · DISTRIBUTED FIRMWARE TECHNICAL LEAD

Four-Axis Inspection Gantry

Moves a leak-detection head over 3 metres of travel per axis, using five small networked controllers.

5 Network Nodes UDP + JSON Schema Collision Interlock

Distributed Node Topology

One microcontroller per motor pair and per sensor head. A master node bridges the operator PC on wired Ethernet to a private Wi-Fi network for the other four nodes.

Motion & Collision Interlock

Commands are in millimetres. Each node converts to steps and homes both axes before it accepts a move. One node owns the collision sensor, and the master rebroadcasts its state so every motor node stops. Built as a single new unit to scan for gas leaks, with no earlier system to replace. Positioning accuracy is 0.1 mm per move, reached with a 30-40-30 motion profile (30% of the move accelerating, 40% at constant speed, 30% decelerating). It ran for a month without stopping in its acceptance test. The controller was later moved from an ATmega2560 to an ESP32.
